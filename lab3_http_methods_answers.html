ЛР3 — методы веб-сервиса StylometrySample

Тема проекта: веб-сервис для карточек текстовых образцов и стилометрических признаков. Бэкенд написан на Go, роутинг выполнен через Gin, работа с БД — через GORM, удаление карточки — SQL UPDATE через курсор.

Локальный адрес для проверки в Postman: http://127.0.0.1:8080. Все API-методы начинаются с /api.

1. Десять HTTP-методов ЛР3

В проекте зарегистрировано 10 API-методов. Ниже указаны URL, тело запроса и пример ответа. Для ленты переход к следующей карточке выполняется тем же методом GET /api/samples/feed, но с query-параметрами stylometry_id и next=true.

№ Метод и URL Что делает Тело запроса Код из лабы
1 GET /api/samples?stylometry_avg_len=12 Возвращает список опубликованных карточек. Фильтр ограничивает среднюю длину предложения. Тело не передаётся. stylometry_api.GET("/samples", APIGetSampleList)
2 GET /api/samples/feed Возвращает одну первую опубликованную карточку для ленты. Тело не передаётся. stylometry_api.GET("/samples/feed", APIGetSampleFeed)
3 GET /api/samples/draft Возвращает черновик текущего пользователя. ID в URL не нужен. Тело не передаётся. stylometry_api.GET("/samples/draft", APIGetSampleDraft)
4 POST /api/samples Создаёт или обновляет черновик, загружает изображение и видео в MinIO. multipart/form-data, не обычный JSON. stylometry_api.POST("/samples", APIPostSampleDraft)
5 PUT /api/samples/draft/publish Публикует черновик текущего пользователя и рассчитывает признаки стилометрии. Тело не передаётся. stylometry_api.PUT("/samples/draft/publish", APIPutSamplePublishDraft)
6 DELETE /api/samples/24 Логически удаляет карточку текущего пользователя: статус меняется на deleted. Тело не передаётся. stylometry_api.DELETE("/samples/:id", APIDeleteSample)
7 POST /api/samples/1/like Ставит или снимает лайк текущего пользователя. { "stylometry_like": 1 } или { "stylometry_like": 0 } stylometry_api.POST("/samples/:id/like", APIPostSampleLike)
8 POST /api/users Регистрирует нового пользователя. { "stylometry_sample_name": "testuser", "stylometry_sample_password": "12345" } stylometry_api.POST("/users", APIPostUserRegister)
9 POST /api/auth/login Заглушка аутентификации для следующей лабораторной. Можно без тела. stylometry_api.POST("/auth/login", APIPostAuthLogin)
10 POST /api/auth/logout Заглушка деавторизации для следующей лабораторной. Можно без тела. stylometry_api.POST("/auth/logout", APIPostAuthLogout)

2. Как методы реализованы в моём коде

Все методы сначала регистрируются в файле stylometry_internal/stylometry_api/stylometry_server.go. Дальше запрос попадает в handler из файла stylometry_api_handler.go. Handler читает параметры запроса, проверяет ошибки и вызывает repository. Repository уже работает с БД через GORM или через SQL-курсор.

Регистрация API-роутов

stylometry_api := stylometry_r.Group("/api")
{
  stylometry_api.GET("/samples", stylometry_stylometryHandler.APIGetSampleList)
  stylometry_api.GET("/samples/feed", stylometry_stylometryHandler.APIGetSampleFeed)
  stylometry_api.GET("/samples/draft", stylometry_stylometryHandler.APIGetSampleDraft)
  stylometry_api.POST("/samples", stylometry_stylometryHandler.APIPostSampleDraft)
  stylometry_api.PUT("/samples/draft/publish", stylometry_stylometryHandler.APIPutSamplePublishDraft)
  stylometry_api.DELETE("/samples/:id", stylometry_stylometryHandler.APIDeleteSample)
  stylometry_api.POST("/samples/:id/like", stylometry_stylometryHandler.APIPostSampleLike)
  stylometry_api.POST("/users", stylometry_stylometryHandler.APIPostUserRegister)
  stylometry_api.POST("/auth/login", stylometry_stylometryHandler.APIPostAuthLogin)
  stylometry_api.POST("/auth/logout", stylometry_stylometryHandler.APIPostAuthLogout)
}

1. GET /api/samples — список опубликованных карточек с фильтром

Handler берёт query-параметр stylometry_avg_len, проверяет, что число находится в диапазоне 0–30, и передаёт значение в repository. 

stylometry_raw_filter := strings.TrimSpace(stylometry_ctx.Query("stylometry_avg_len"))

var stylometry_max_avg_len *float64
if stylometry_raw_filter != "" {
  stylometry_num, stylometry_err := stylometryParseFloat(stylometry_raw_filter)
  if stylometry_err != nil || stylometry_num < stylometryAvgLenMin || stylometry_num > stylometryAvgLenMax {
    stylometry_ctx.JSON(http.StatusBadRequest, gin.H{
      "error": "stylometry_avg_len должен быть числом от 0 до 30",
    })
    return
  }
  stylometry_max_avg_len = &stylometry_num
}

stylometry_samples, stylometry_err := stylometry_h.Repository.FilteredSamples(stylometry_max_avg_len)

В repository фильтрация выполняется через ORM-запрос GORM. Сначала берутся только опубликованные записи, потом добавляется условие по средней длине предложения. 

stylometry_query := stylometry_repository.DB.
  Preload("Likes").
  Where("\"Status\" = ?", model.StatusPublished)

if stylometry_max_avg_len != nil {
  stylometry_query = stylometry_query.Where(
    "\"AverageSentenceLength\" <= ?",
    *stylometry_max_avg_len,
  )
}

stylometry_err := stylometry_query.
  Order("\"ID\" ASC").
  Find(&stylometry_samples).Error

2. GET /api/samples/feed — лента

Handler читает stylometry_id и next=true. Если id не передан, repository вернёт первую опубликованную карточку. Если передан id и next=true, repository ищет следующую карточку с большим id. 

stylometry_raw_id := strings.TrimSpace(stylometry_ctx.Query("stylometry_id"))
stylometry_next := strings.EqualFold(strings.TrimSpace(stylometry_ctx.Query("next")), "true")

stylometry_sample, stylometry_ok, stylometry_err :=
  stylometry_h.Repository.FeedSample(stylometry_sample_id, stylometry_next)

Важная часть реализации: БД возвращает одну строку через First. Если следующей карточки нет, выполняется второй запрос, который возвращает первую карточку, поэтому лента зациклена. 

if stylometry_id != nil && stylometry_next {
  stylometry_query = stylometry_query.Where("\"ID\" > ?", *stylometry_id)
}

stylometry_err := stylometry_query.
  Order("\"ID\" ASC").
  First(&stylometry_sample).Error

if errors.Is(stylometry_err, gorm.ErrRecordNotFound) && stylometry_id != nil && stylometry_next {
  stylometry_err = stylometry_repository.DB.
    Preload("Likes").
    Where("\"Status\" = ?", model.StatusPublished).
    Order("\"ID\" ASC").
    First(&stylometry_sample).Error
}

3. GET /api/samples/draft — черновик текущего пользователя

Handler сам не принимает id черновика. Он вызывает DraftSample(), а repository ищет черновик по текущему пользователю и статусу draft. 

stylometry_draft, stylometry_has_draft, stylometry_err := stylometry_h.Repository.DraftSample()

if !stylometry_has_draft {
  stylometry_ctx.JSON(http.StatusOK, gin.H{
    "has_draft": false,
    "draft":     nil,
  })
  return
}
stylometry_err := stylometry_repository.DB.
  Preload("Likes").
  Where("\"CreatorID\" = ? AND \"Status\" = ?",
    stylometryCurrentUserID(),
    model.StatusDraft,
  ).
  First(&stylometry_sample).Error

4. POST /api/samples — создание/обновление черновика и MinIO

Этот метод принимает multipart/form-data, потому что кроме текста передаются два файла: изображение и видео. Handler читает поля формы, достаёт файлы, загружает их в MinIO и передаёт полученные URL в repository. 

stylometry_text_creator := strings.TrimSpace(stylometry_ctx.PostForm("stylometry_text_creator"))
stylometry_description := strings.TrimSpace(stylometry_ctx.PostForm("stylometry_sample_descr"))

stylometry_image_file, stylometry_err :=
  stylometryAPIFormFile(stylometry_ctx, "stylometry_image", "image", "stylometry_sample_image")

stylometry_video_file, stylometry_err :=
  stylometryAPIFormFile(stylometry_ctx, "stylometry_video", "video", "stylometry_sample_video")
stylometry_image_url, stylometry_err := media.UploadFile(
  stylometry_ctx.Request.Context(),
  stylometry_image_file,
  "stylometry_images",
)

stylometry_video_url, stylometry_err := media.UploadFile(
  stylometry_ctx.Request.Context(),
  stylometry_video_file,
  "stylometry_videos",
)

Repository сначала проверяет, есть ли уже черновик у пользователя. Если есть — обновляет его через GORM Updates. Если нет — создаёт новую запись через GORM Create. 

stylometry_existing, stylometry_found, stylometry_err := stylometry_repository.DraftSample()
stylometry_metrics := analysis.AnalyzeText(stylometry_text)

if stylometry_found {
  stylometry_updates := map[string]interface{}{
    "TextCreator":           stylometry_text_creator,
    "ShortDescription":      stylometry_text,
    "ImageURL":              stylometry_image_url,
    "VideoURL":              stylometry_video_url,
    "AverageSentenceLength": stylometry_metrics.AverageSentenceLength,
    "ConjunctionFrequency":  stylometry_metrics.ConjunctionFrequency,
  }
  stylometry_err = stylometry_repository.DB.Model(&model.Sample{}).
    Where("\"ID\" = ?", stylometry_existing.ID).
    Updates(stylometry_updates).Error
}
stylometry_sample := model.Sample{
  TextCreator:           stylometry_text_creator,
  ShortDescription:                 stylometry_text,
  Status:                model.StatusDraft,
  ImageURL:              stylometry_image_url,
  VideoURL:              stylometry_video_url,
  AverageSentenceLength: stylometry_metrics.AverageSentenceLength,
  ConjunctionFrequency:  stylometry_metrics.ConjunctionFrequency,
  CreatorID:             stylometryCurrentUserID(),
}
stylometry_err = stylometry_repository.DB.Create(&stylometry_sample).Error

5. PUT /api/samples/draft/publish — публикация черновика

Handler сначала получает черновик текущего пользователя. Потом вызывает анализ текста и передаёт рассчитанные значения в repository. 

stylometry_draft, stylometry_has_draft, stylometry_err := stylometry_h.Repository.DraftSample()
stylometry_metrics := analysis.AnalyzeText(stylometry_draft.ShortDescription)

stylometry_err = stylometry_h.Repository.PublishDraft(
  stylometry_draft.ShortDescription,
  stylometry_metrics.AverageSentenceLength,
  stylometry_metrics.ConjunctionFrequency,
)

Repository меняет статус только у черновика текущего пользователя. Здесь же заполняется UpdatedAt. 

stylometry_updated_at := time.Now()
stylometry_result := stylometry_repository.DB.
  Model(&model.Sample{}).
  Where("\"CreatorID\" = ? AND \"Status\" = ?",
    stylometryCurrentUserID(),
    model.StatusDraft,
  ).
  Updates(map[string]interface{}{
    "ShortDescription":      stylometry_description,
    "AverageSentenceLength": stylometry_avg_len,
    "ConjunctionFrequency":  stylometry_conj_freq,
    "Status":                model.StatusPublished,
    "UpdatedAt":             &stylometry_updated_at,
  })

6. DELETE /api/samples/:id — логическое удаление через SQL-курсор

Handler берёт id из URL и вызывает repository. Здесь специально используется не ORM-удаление, а SQL-запрос UPDATE ... RETURNING через QueryContext. 

stylometry_id, stylometry_err :=
  strconv.ParseUint(strings.TrimSpace(stylometry_ctx.Param("id")), 10, 64)

stylometry_err = stylometry_h.Repository.DeleteSampleSQL(uint(stylometry_id))
stylometry_sql_db, stylometry_err := stylometry_repository.DB.DB()

stylometry_rows, stylometry_err := stylometry_sql_db.QueryContext(
  context.Background(),
  "UPDATE \"StylometrySamples\" SET \"Status\" = $1
   WHERE \"ID\" = $2
     AND \"Status\" <> $3
     AND \"CreatorID\" = $4
   RETURNING \"ID\"",
  string(model.StatusDeleted),
  stylometry_id,
  string(model.StatusDeleted),
  stylometryCurrentUserID(),
)

Курсор здесь — это stylometry_rows. По нему код проверяет, вернул ли SQL-запрос удалённую строку. Если строка есть, удаление успешно. Если строки нет, значит карточка не найдена, уже удалена или принадлежит другому пользователю. 

if stylometry_rows.Next() {
  var stylometry_deleted_id uint
  if stylometry_err := stylometry_rows.Scan(&stylometry_deleted_id); stylometry_err != nil {
    return stylometry_err
  }
  return stylometry_rows.Err()
}

7. POST /api/samples/:id/like — лайк

Handler читает id карточки из URL и тело запроса. Значение может прийти как stylometry_like или как like. Допускаются только значения 0 и 1. 

type stylometryAPILikeRequest struct {
  StylometryLike *int `form:"stylometry_like" json:"stylometry_like"`
  Like           *int `form:"like" json:"like"`
}
if stylometry_like_value != 0 && stylometry_like_value != 1 {
  stylometry_ctx.JSON(http.StatusBadRequest, gin.H{
    "error": "stylometry_like должен быть 0 или 1",
  })
  return
}

stylometry_ok, stylometry_err :=
  stylometry_h.Repository.SetLike(uint(stylometry_id), stylometry_like_value)

В repository сначала проверяется, что карточка существует и опубликована. Потом создаётся запись в таблице лайков или удаляется существующая запись. 

stylometry_err := stylometry_repository.DB.Model(&model.Sample{}).
  Where("\"ID\" = ? AND \"Status\" = ?",
    stylometry_id,
    model.StatusPublished,
  ).
  Count(&stylometry_count).Error
stylometry_like := model.Like{
  UserID:       stylometryCurrentUserID(),
  SampleID: stylometry_id,
}

if stylometry_like_value == 1 {
  stylometry_err = stylometry_repository.DB.
    Clauses(clause.OnConflict{DoNothing: true}).
    Create(&stylometry_like).Error
  return true, stylometry_err
}
stylometry_err = stylometry_repository.DB.
  Where("\"UserID\" = ? AND \"SampleID\" = ?",
    stylometryCurrentUserID(),
    stylometry_id,
  ).
  Delete(&model.Like{}).Error

8. POST /api/users — регистрация пользователя

Handler привязывает JSON или form-data к структуре stylometryAPIUserRequest. Если пароль не передан, подставляется значение по умолчанию. 

type stylometryAPIUserRequest struct {
  Name     string `form:"stylometry_sample_name" json:"stylometry_sample_name"`
  Password string `form:"stylometry_sample_password" json:"stylometry_sample_password"`
}
stylometry_name := strings.TrimSpace(stylometry_request.Name)
stylometry_password := strings.TrimSpace(stylometry_request.Password)

if stylometry_password == "" {
  stylometry_password = "stylometry123"
}

stylometry_user, stylometry_err :=
  stylometry_h.Repository.RegisterUser(stylometry_name, stylometry_password)

В repository пользователь создаётся через GORM Create.

stylometry_user := model.User{
  Name:     stylometry_name,
  Password: stylometry_password,
}
stylometry_err := stylometry_repository.DB.Create(&stylometry_user).Error

9–10. POST /api/auth/login и POST /api/auth/logout — заглушки

Эти методы пока не выполняют настоящую авторизацию. Они нужны для структуры API и следующей лабораторной. Сейчас они просто возвращают JSON-ответ. 

func (stylometry_h *SampleHandler) APIPostAuthLogin(stylometry_ctx *gin.Context) {
  stylometry_ctx.JSON(http.StatusOK, gin.H{
    "authenticated":           true,
    "stylometry_current_user": stylometryAPIUserID(),
    "stylometry_auth_comment": "заглушка для лабораторной работы №4",
  })
}

func (stylometry_h *SampleHandler) APIPostAuthLogout(stylometry_ctx *gin.Context) {
  stylometry_ctx.JSON(http.StatusOK, gin.H{
    "deauthenticated":         true,
    "stylometry_auth_comment": "заглушка для лабораторной работы №4",
  })
}

Фиксированный текущий пользователь

Во всех методах текущий пользователь берётся не из клиента, а через функцию-singleton. Это соответствует условию лабораторной: авторизация пока не реализуется, пользователь зафиксирован. 

const stylometrySampleFixedUserID uint = 1

func CurrentUser() *CurrentUserInfo {
  stylometrySampleCurrentUserOnce.Do(func() {
    stylometrySampleCurrentUser = &CurrentUserInfo{
      ID: stylometrySampleFixedUserID,
    }
  })

  return stylometrySampleCurrentUser
}

Сериализация ответа

После чтения модели из БД handler отдаёт не саму модель GORM, а DTO из serializer. Поэтому клиент получает только нужные поля, а внутренние связи и статус не выводятся напрямую. 

return SampleResponseDTO{
  ID:                    stylometry_sample.ID,
  TextCreator:           stylometry_sample.TextCreator,
  ShortDescription:                 stylometry_sample.ShortDescription,
  ImageURL:              stylometry_sample.ImageURL,
  VideoURL:              stylometry_sample.VideoURL,
  AverageSentenceLength: stylometry_sample.AverageSentenceLength,
  ConjunctionFrequency:  stylometry_sample.ConjunctionFrequency,
  LikesCount:            len(stylometry_sample.Likes),
  IsCurrentUserCreator:  stylometry_is_creator,
}

4. Как реализован метод лайка

Метод лайка реализован как POST /api/samples/:id/like. В теле запроса передаётся stylometry_like: значение 1 ставит лайк, значение 0 снимает лайк. Пользователь берётся не с клиента, а из функции-singleton. 

{
  "stylometry_like": 1
}

Модель лайка:

type Like struct {
  ID       uint `gorm:"primaryKey;column:ID"`
  UserID       uint `gorm:"column:UserID;not null"`
  SampleID uint `gorm:"column:SampleID;not null"`
}

Пользователь берётся через singleton:

const stylometrySampleFixedUserID uint = 1

func CurrentUser() *CurrentUserInfo {
  stylometrySampleCurrentUserOnce.Do(func() {
    stylometrySampleCurrentUser = &CurrentUserInfo{
      ID: stylometrySampleFixedUserID,
    }
  })

  return stylometrySampleCurrentUser
}

Handler проверяет id, тело запроса и вызывает репозиторий:

stylometry_ok, stylometry_err := stylometry_h.Repository.SetLike(
  uint(stylometry_id),
  stylometry_like_value,
)

Repository проверяет, что карточка опубликована, и ставит или снимает лайк:

if stylometry_like_value == 1 {
  stylometry_err = stylometry_repository.DB.
    Clauses(clause.OnConflict{DoNothing: true}).
    Create(&stylometry_like).Error
  return true, stylometry_err
}

stylometry_err = stylometry_repository.DB.
  Where("\"UserID\" = ? AND \"SampleID\" = ?",
    stylometryCurrentUserID(),
    stylometry_id,
  ).
  Delete(&model.Like{}).Error

OnConflict{DoNothing: true} нужен, чтобы повторный лайк от того же пользователя не создавал дубль. После изменения лайка карточка перечитывается из БД, и в ответе возвращается новое значение stylometry_sample_likes_count.

5. Схема HTTPS

HTTPS — это HTTP, который передаётся внутри защищённого TLS-соединения. В моей лабораторной локально используется обычный HTTP на 127.0.0.1:8080, но в реальной публикации сервис можно закрыть HTTPS через сертификат или reverse proxy. 

Клиент/Postman/SPA
      |
      | 1. DNS: получить IP домена
      v
Сервер
      |
      | 2. TCP handshake: SYN -> SYN/ACK -> ACK
      v
TLS handshake
      |
      | 3. Сервер отправляет сертификат
      | 4. Клиент проверяет сертификат через центр сертификации
      | 5. Стороны договариваются о ключах шифрования
      v
HTTP внутри TLS
      |
      | 6. GET /api/samples или POST /api/samples
      | 7. Ответ JSON передаётся в зашифрованном виде

Код из лабы показывает локальный HTTP-сервер:

if stylometry_err := stylometry_r.Run(":8080"); stylometry_err != nil {
  logrus.Fatal(stylometry_err)
}

Если запускать Gin напрямую по HTTPS, используется сертификат и ключ: 

stylometry_r.RunTLS(":443", "cert.pem", "key.pem")

6. Контрольные вопросы

Что такое веб-сервис?

Веб-сервис — это серверная часть приложения, которая принимает запросы по сети и возвращает данные в стандартном формате, чаще всего JSON. В моей лабораторной веб-сервис отдаёт карточки текстовых образцов, принимает файлы, меняет статусы и работает с таблицами БД. 

stylometry_api := stylometry_r.Group("/api")
{
  stylometry_api.GET("/samples", stylometry_stylometryHandler.APIGetSampleList)
  stylometry_api.POST("/samples", stylometry_stylometryHandler.APIPostSampleDraft)
}

Что такое REST?

REST — это стиль проектирования API, где данные представлены как ресурсы, у каждого ресурса есть URL, а действие задаётся HTTP-методом. Например, ресурс карточек — /api/samples: GET получает данные, POST создаёт, DELETE удаляет. 

GET    /api/samples
POST   /api/samples
DELETE /api/samples/:id

Что такое RPC?

RPC — это подход, где клиент вызывает удалённую процедуру как функцию. В REST главный акцент на ресурсе, а в RPC — на действии. В моей лабораторной основа API REST, но методы публикации и лайка похожи на RPC, потому что они выполняют конкретное действие над карточкой. 

PUT  /api/samples/draft/publish
POST /api/samples/:id/like

Заголовки HTTP

Заголовки HTTP передают служебную информацию о запросе и ответе. Например: Content-Type сообщает формат тела, Accept — какой формат ждёт клиент, Authorization используется для токена авторизации. 

Content-Type: application/json
Accept: application/json

Для загрузки изображения и видео в моей лабораторной используется другой тип:

Content-Type: multipart/form-data

Методы HTTP

Основные методы: GET — получить данные, POST — создать или выполнить действие, PUT — полностью изменить состояние ресурса, DELETE — удалить ресурс. В моей лабораторной используются все эти методы. 

stylometry_api.GET("/samples", stylometry_stylometryHandler.APIGetSampleList)
stylometry_api.POST("/samples", stylometry_stylometryHandler.APIPostSampleDraft)
stylometry_api.PUT("/samples/draft/publish", stylometry_stylometryHandler.APIPutSamplePublishDraft)
stylometry_api.DELETE("/samples/:id", stylometry_stylometryHandler.APIDeleteSample)

Версии HTTP

HTTP/0.9 был самым простым и поддерживал только получение HTML. HTTP/1.0 добавил заголовки и коды статусов. HTTP/1.1 добавил постоянные соединения и обязательный заголовок Host. HTTP/2 поддерживает мультиплексирование запросов в одном соединении. HTTP/3 работает поверх QUIC и UDP, что уменьшает задержки.

Для кода моей лабораторной версия HTTP обычно выбирается сервером и клиентом автоматически, а сам обработчик в Go остаётся тем же.

Что такое HTTPS?

HTTPS — это защищённый вариант HTTP. Он использует TLS для шифрования данных, проверки подлинности сервера и защиты от подмены трафика. Для пользователя отличие видно по схеме адреса: https:// вместо http://. 

http://127.0.0.1:8080/api/samples   // локальная лабораторная
https://example.ru/api/samples       // публикация с TLS-сертификатом

Модель OSI ISO

Модель OSI описывает передачу данных по сети в 7 уровнях. Моя лабораторная работает на прикладном уровне, потому что использует HTTP API.
